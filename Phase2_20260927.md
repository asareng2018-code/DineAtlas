# Phase 2 – Industry-Standard Enhancements

Date: 2026-09-27

## 1. Overview

Phase 2 upgrades the Singapore restaurant discovery MVP from a functional prototype into a production-quality, user-centric web application. It builds directly on the Phase 1 foundation established in Next.js, Express, PostgreSQL, Mapbox, Elasticsearch, and Docker.

The focus is to improve user experience, performance, compliance, personalization, and deployment readiness while maintaining the architecture that already works for a scalable restaurant discovery platform.

---

## 2. Phase 1 Baseline

The current app already includes:

- Next.js frontend with landing page and map page
- Express backend with restaurant and filter APIs
- PostgreSQL schema scaffold
- Elasticsearch indexing script
- Google OAuth scaffold
- Plausible analytics integration
- Docker and GitHub Actions setup
- Security and validation foundation

This means Phase 2 should not start from zero. It should enhance and connect the existing structure rather than rebuild it from scratch.

---

## 3. Phase 2 Objectives

Phase 2 aims to satisfy the following industry-standard requirements:

- Progressive Web App (PWA) support for offline access and app-like behavior
- Real geolocation-based distance calculations
- Modern SSR-based frontend for SEO and performance
- Scalable backend with PostgreSQL persistence
- Accessibility compliance (WCAG 2.1 AA)
- User accounts with social login (Google, Facebook, Apple)
- Favorite restaurants and offer subscriptions
- Analytics tracking
- Core Web Vitals optimization
- HTTPS, CSRF protection, and input validation
- Multilingual support in English, Mandarin, Malay, and Tamil

---

## 4. Recommended Technical Architecture

### Frontend
- Next.js 16+ with App Router
- TypeScript
- Tailwind CSS
- PWA support via next-pwa or built-in app manifest/workbox configuration
- Geolocation + user location permissions
- i18n support for EN, ZH, MS, TA
- Accessibility-first UI patterns

### Backend
- Node.js + Express.js
- PostgreSQL for user, restaurant, favorites, subscription, and offer data
- Redis optional for caching and session optimization
- Passport.js for social authentication
- Express rate limiting, helmet, CSRF protection

### Data / Search
- PostgreSQL as system of record
- Elasticsearch for restaurant search, filtering, ranking, and location-aware discovery
- PostGIS optional for distance queries and geospatial indexing

### DevOps / Security
- HTTPS via Nginx reverse proxy or cloud load balancer
- Environment-specific secrets management
- Helmet, CORS rules, input validation, rate limiting
- CI/CD validation for build, lint, tests, and smoke checks

## 5. Phase 2 Workstreams

### A. PWA and Mobile UX

#### Requirements
- Add manifest.json and install prompt
- Offline caching for key pages and restaurant data
- Add app icons and splash screen support
- Improve mobile navigation and touch-first interactions

#### Deliverables
- PWA manifest configuration
- Service worker / caching strategy
- Offline fallback page for no-network state
- Installable “Add to Home Screen” experience

#### Acceptance Criteria
- App installs on supported devices
- Offline shell loads successfully
- Core restaurant pages remain usable without Internet

---

### B. Geolocation and Distance Logic

#### Requirements
- Detect user location with browser geolocation API
- Calculate real-time distance to restaurants
- Sort by nearest location when permission is granted
- Support fallback behavior when permissions are denied

#### Deliverables
- `navigator.geolocation` integration
- Distance calculation utility using Haversine formula or PostGIS
- Frontend location state and “Near me” filtering
- API route for location-aware restaurant queries

#### Acceptance Criteria
- User can enable location-based listing
- Restaurants are sorted by proximity
- App handles permission rejection gracefully

---

### C. Authentication and User Accounts

#### Requirements
- Social login with Google, Facebook, and Apple
- User profiles and account status
- Protected favorite actions and offer subscriptions

#### Deliverables
- Passport strategy setup for Google, Facebook, Apple
- User table in PostgreSQL
- Session management and login/logout flows
- Secure profile endpoints

#### Acceptance Criteria
- User can sign in with social providers
- Session is secure and persisted
- Authenticated actions are protected

---

### D. Favorites and Offer Subscriptions

#### Requirements
- Save favorite restaurants
- Track saved restaurants per user
- Allow users to subscribe to promotional offers
- Show offer preferences by cuisine or neighborhood

#### Deliverables
- `favorites` table
- `subscriptions` table
- Favorite toggle UI and saved list page
- Offer preference controls and email/newsletter opt-ins

#### Acceptance Criteria
- User can add/remove favorites
- Favorites persist across sessions
- Users can subscribe/unsubscribe from offers

---

### E. Accessibility and Inclusive UX

#### Requirements
- Implement WCAG 2.1 AA-compliant patterns
- Keyboard navigation support
- Color contrast and focus states
- Screen-reader-friendly labels and semantics
- Reduced motion and responsive layout support

#### Deliverables
- Semantic HTML updates
- ARIA labels for interactive controls
- Focus treatment and skip links
- Accessibility testing with Lighthouse and axe

#### Acceptance Criteria
- No critical accessibility issues in audits
- Keyboard users can navigate the app fully
- Page content is understandable to assistive tech

---

### F. Analytics and Performance

#### Requirements
- Keep analytics lightweight and privacy-friendly
- Track page views, click events, filters, map usage, and conversions
- Maintain fast load and stable layout performance

#### Deliverables
- Plausible or Google Analytics integration
- Event tracking for restaurant discovery flows
- Core Web Vitals optimization improvements

#### Acceptance Criteria
- Lighthouse performance is in a strong range
- Key user journeys are measurable
- Metrics are available without harming UX

---

### G. Security and Compliance

#### Requirements
- HTTPS in production
- CSRF protection for authenticated actions
- Input validation for all API endpoints
- Rate limits and abuse prevention
- Safe user content and session handling

#### Deliverables
- `helmet` / secure headers
- CSRF middleware for state-changing actions
- Request validation on all endpoints
- Production deployment security hardening

#### Acceptance Criteria
- No unvalidated inputs reach database logic
- Authenticated actions are protected against CSRF
- Production environment uses secure transport

---

### H. Multilingual Support

#### Requirements
- Support English, Mandarin, Malay, and Tamil
- Localized labels, filter values, and content fragments
- Region-aware language switching UI

#### Deliverables
- `next-intl` or equivalent locale setup
- Translation files for EN, ZH, MS, TA
- Locale-aware formatting for numbers and dates
- Language switcher in header or settings panel

#### Acceptance Criteria
- Switching language updates UI content correctly
- All key flows remain fully localized
- Core pages render in all supported languages

## 9. Definition of Done for Phase 2

The implementation is considered complete when all of the following are true:

- PWA installability and offline caching work on supported browsers
- Geolocation-based distance filtering functions correctly
- Users can log in with Google, Facebook, and Apple
- Favorites and offer subscriptions work end-to-end
- App meets WCAG 2.1 AA standards in key user journeys
- English, Mandarin, Malay, and Tamil are fully supported
- Analytics are active and meaningful
- Core Web Vitals are acceptable on the main pages
- HTTPS, validation, and CSRF protections are active in production settings
- Final deployment verified on a live environment

## 10. Recommended Next Step

The next action is to move from the Phase 1 foundation into Phase 2 implementation in the following order:

1. PWA + offline UX
2. Geolocation and location-aware filtering
3. Authentication and user profiles
4. Favorites and subscriptions
5. Accessibility and i18n
6. Security and production hardening
7. Analytics and performance tuning
8. Final QA and deployment

This sequence keeps the project stable while gradually transforming the MVP into a standards-compliant, modern restaurant discovery application.
