# Phase 1 – MVP Website Implementation Summary

Date: 2026-09-27

## Overview
This project sets up a full-stack web application for a Singapore restaurant discovery and promotion platform. The Phase 1 implementation focuses on project scaffolding, frontend UI, backend API, database schema, search indexing, deployment tooling, and foundational security/testing pieces.

## Architecture

### Frontend
- Next.js app with Tailwind CSS
- Responsive landing page and restaurant listing UI
- Map page using Mapbox GL JS for location visualization
- Plausible analytics script injected at the app shell level

### Backend
- Express.js API serving restaurant and filter data
- CORS enabled for frontend access
- Validation middleware using `express-validator`
- Passport.js setup with Google OAuth scaffolding
- Session support for authenticated flows

### Data and Search
- PostgreSQL schema scaffold for `restaurants`
- Elasticsearch indexing script for restaurant documents
- Filter metadata endpoint exposing supported values like cuisine, location, halal status

### Deployment / DevOps
- Dockerfiles for frontend and backend
- Docker Compose for local orchestration
- GitHub Actions workflow for CI/CD placeholder pipeline

## Project Structure

- `frontend/` – Next.js app
- `backend/` – Express API
- `database/` – PostgreSQL schema
- `search/` – Elasticsearch indexing utility
- `.env.example` – environment variable template
- `docker-compose.yml` – local container orchestration
- `.github/workflows/deploy.yml` – CI/CD pipeline

## Notable Notes

- The project is best described as a strong Phase 1 foundation and MVP scaffolding.
- Some external services (PostgreSQL, Elasticsearch, real OAuth credentials, and a real Mapbox token) are configured as placeholders and still require live infrastructure for full production behavior.
- The frontend and backend currently run as separate apps, which aligns with the architecture decision for scalability and separation of concerns.
